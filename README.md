# phy-sim

Simulation environment for Nestua's custom OFDM video PHY. Plan and
rationale: `hardware/pcb/radio/phy-simulator-plan-2026-10-24.html`.

```
harness/      Python: waveform definition, Sionna chain, impairments, sweep runner
experiments/  one script per hypothesis, writes results/<name>.json (+ .png)
results/      committed JSON results, the record of what was tried
modem/        Zig product modem (fixed-point, C ABI), NumPy twins in modem/ref/
vectors/      golden vectors per block, generated by modem/ref/
rtl/          Verilog blocks, each with a cocotb test
tests/        pytest gates; `make check` runs everything
```

## Setup (macOS)

```
brew install verilator icarus-verilog
# Zig: official tarball, Homebrew's 0.17.0 build is broken on macOS 26
#   https://ziglang.org/download/  ->  ~/.local/zig/0.17.0, symlink ~/.local/bin/zig
python3.12 -m venv .venv && .venv/bin/pip install -r requirements.txt
make check
```

Sionna runs on CPU on Apple Silicon (the Metal backend fails inside the
LDPC encoder as of Sionna 2.2.0). Long sweeps belong on a CUDA machine.

## Setup (Windows, WSL2 Ubuntu 24.04)

As in `HANDOFF.md`, with two differences found on the first install:
Ubuntu's Verilator (5.020) is older than cocotb 2 accepts (5.036), so build
the `stable` branch from source into `/usr/local`; and install the CUDA
build of torch (`--index-url https://download.pytorch.org/whl/cu126`)
before `requirements.txt`. Keep the clone on the Linux filesystem
(`~/phy-sim`), not under `/mnt/<drive>`. Experiments pick `cuda:0`
automatically when it exists (`harness.sweep.default_device`).

On the RTX 3060 Ti the OFDM chain does about 4,500 frames/s for QPSK and
2,500 for 64-QAM at batch 250: the decoder, demapper and equalizer are
`torch.compile`d (the decoder alone is 8x faster that way, bit-identical),
the TDL path gains are generated at a decimated rate and interpolated,
and the genie LMMSE estimator precomputes one filter per SNR point. The
first call of each block per input shape compiles for about 20 s.
WSL2's CUDA spills to system RAM instead of failing when the 8 GB run out,
and then everything is 10x slower; keep the peak under about 6 GB.

## Workflow

1. A hypothesis is a script in `experiments/`. Copy the closest one, change the
   waveform or MCS table it imports, run it with `make <name>` or
   `.venv/bin/python -I experiments/<name>.py`.
2. It writes `results/<name>.json` (parameters, git revision, every SNR point
   with frame and error counts, the Es/N0 at 10 % and 1 % FER) and a PNG.
3. Commit the JSON. `make check` includes the gates in `tests/`, which read the
   committed JSON and fail on implausible numbers or on drift from the
   reference curve.

`harness/waveform.py` is the single source of the numerology and MCS table.
`harness/chain.py` holds the Sionna chains: `AwgnLink` (per-RE, M1) and
`OfdmLink` (time-domain OFDM with Kronecker pilots, LS / genie-LMMSE /
perfect channel estimation, an optional TDL fading channel, and impairment
hooks). `harness/impairments.py` has the RF models as plain torch functions
`fn(x, fs)`: CFO, sampling clock offset, Wiener phase noise, Rapp PA, IQ
imbalance, AGC plus ADC, a Wi-Fi burst, and an `oversampled()` wrapper for
nonlinearities. `harness/sweep.py` is the Monte Carlo runner: each SNR point
runs until 100 frame errors or the frame cap, and a sweep stops once a
point shows zero errors at the cap.

Experiments from e002 on take `--profile quick|reference` (`make e002
PROFILE=quick`). Quick runs write `results/<name>.quick.json`, which is not
committed; rank hypotheses with them, then commit the reference run.

## The Zig modem (L2)

`modem/` builds `libnestuaphy.so` (`make modem`, ReleaseFast, native CPU).
M3 is the whole chain in f32: `src/ldpc.zig` (5G LDPC built as Sionna
builds it, flooding sum-product decoder on the QC structure, 8-lane SIMD
check nodes), `src/qam.zig` (Gray QAM, exact LLRs), `src/ofdm.zig` (radix-2
FFT), `src/modem.zig` (frame TX and RX: grid, pilots, interleaver, linear
phase tracker, LS plus a 2D filter, one-tap LMMSE, threads over the batch)
and `src/root.zig` (the C ABI). The base graph tables in `src/ldpc/` are
Sionna's.

`harness/modem.py` is the Python side. `ZigModem` wraps one configured
modem; `zig_modem_for(link)` builds it from an `OfdmLink` (numerology,
codeword plan, pilots, interleaver). The receiver's estimator filter comes
from `GenieLmmseEstimator.filters(no)` and is set per noise level.
`ZigOfdmLink` runs Zig TX, Sionna's channel and impairments, Zig RX, and
with `compare=True` Sionna's receiver on the same samples. The single
blocks (`ldpc_encode`, `ldpc_decode`, `qam_map`, `qam_demap`) are exported
for tests. On the 5900X the receiver decodes about 1,600 frames/s
(16qam-1/2, 24 threads, 20 iterations at the waterfall; early stop makes it
faster above).

## The fixed-point modem (L2, M4)

`src/fxmodem.zig` is the product modem: the whole frame in integer
arithmetic with chosen widths, the golden model for the RTL.
`FxModem(true)` is fixed point; `FxModem(false)` is the same algorithm in
floating point (no rounding or saturation), which the fixed-point loss is
measured against. The blocks:
- **Shared pieces:** `src/fx.zig` holds rounding, saturation, CORDIC and the
  16-bit radix-2 FFT with Q16 twiddles. `src/fxldpc.zig` is the layered
  offset min-sum decoder. `src/tables.zig` generates the Gold-sequence
  pilots and the interleaver.
- **TX:** integer QAM levels, a 16-bit IFFT and a 12-bit DAC.
- **RX, from 12-bit ADC samples:** FFT, LS without division, then the
  separable estimator: a 32-tap frequency FIR per pilot symbol and time
  weights per data symbol. Then the CORDIC phase tracker, removing half the
  fitted ramp. The max-log demapper needs no division (metric `u L^2 - 2 z L`
  with `z = Y h*`, `u = a |h|^2`) and produces 6-bit LLRs at 0.25 nat per
  LSB, with the per-frame scale capped. Decoding uses 6-bit messages and an
  8-bit APP.

`harness/twin.py` is the NumPy twin of every block, written to be read,
not to be fast. `tests/test_m4_twins.py` holds it bit exact against the Zig
modem, from the tables to the decoded bits of whole frames through Sionna's
channel. `harness/design.py` designs the estimator offline (constrained
Wiener, unbiased, one tap set per 3 dB of SNR). `harness/fxmodem.py` has
the wrappers: `FxModem`, `FixedPoint` (the widths), `agc_adc`, and
`FxOfdmLink`, which runs the genie f32, product float and product fixed
receivers on the same samples.

`make vectors` writes the golden vectors to `vectors/` (committed). Each
frame file carries its configuration, taps, inputs and every intermediate
result. `tests/test_m4_vectors.py` replays them through the Zig modem and
the twin, so any change to a fixed-point block shows up as a vector diff.
Regenerate the vectors only for an intended change. The fixed receiver
decodes 9,000 to 24,000 frames/s on the 5900X.

## The synchroniser (L2, M5)

`src/fxsync.zig` finds a frame in a buffer of 12-bit ADC samples and hands
the aligned, derotated frame to the M4 receiver (`FxModem.rx` with
`l_min = 0`). The frame now starts with a one-slot preamble: nine
repetitions of a 32-sample sequence, the subcarriers that are multiples
of 8, with QPSK from the Gold sequence (seed picked for a 4.3 dB PAPR), at
the data symbols' power. The synchroniser:
- **detects and coarsely times** on the lag-32 autocorrelation against the
  energy (running sums, no division), and takes the coarse CFO from its
  CORDIC angle (range +-156 kHz);
- **times finely** on the channel impulse response of the first pilot
  symbol (FFT, conjugate pilot, IFFT, reusing the FFT), picking the first
  path above a fraction of the peak and the noise floor, and rejects a
  detection whose CIR has no clear peak;
- **refines the CFO** from the cyclic prefixes (lag 256, range +-19.5 kHz);
- **aligns** the frame with a 32-bit NCO and the CORDIC, 4 samples before
  the first path.

`harness/sync.py` holds the same algorithm in floating point
(`FloatSync`), the preamble, and the ctypes wrapper (`FxSync`);
`harness/twin.py` (`TwinSync`) is its bit-exact NumPy twin.
`harness/synclink.py` puts each frame behind its preamble at a random
time in a buffer. It applies the oscillators' full offset (CFO in +-116
kHz, 20 ppm SCO, PLL noise), Sionna's channel, the AGC and the ADC, then
runs the synchroniser and the receivers. It compares cold (per frame),
warm (a frequency loop over many frames), aided (warm less the predicted
line-of-sight Doppler) and genie synchronisation. `make vectors` also
writes `vectors/sync_*.npz`; `tests/test_m5_sync.py` replays them. The
fixed synchroniser takes about 0.08 ms per frame on one core.

## The link layer and video model (M6)

Two steps, so that the slow part runs once:

1. **PHY traces** (`harness/phytrace.py`, e016). The whole product chain
   of M5 runs on consecutive frames of a fading channel that is continuous
   in time (`harness/fading.py`: Sionna's TDL sum of sinusoids with its
   random draws kept per link). For every frame and MCS the trace stores
   the frame's decoding threshold: the lowest mean Es/N0 at which that
   frame, with its own channel, noise shape, timing and oscillators,
   decodes, found by bisection on one noise draw. A frame at mean Es/N0
   `s` then decodes iff `s >= thr`, for any SNR trajectory. The traces
   are `results/e016_traces/<channel>.npz` (committed), about a minute of
   air time per fading channel.
2. **Link layer and video** (`harness/linklayer.py`, e017), slot by slot
   over a trace: a TDD superframe of 23 PHY frames (22 downlink, one
   uplink), one link packet per frame, and nestua-zig's rules on top
   (Reed-Solomon blocks with its tail rules, NACK-driven retransmission,
   LTR re-anchor or IDR recovery, the ladder), with every rule a
   `LinkConfig` field so it can be tuned. The video is a synthetic 1080p60
   stream at the rung's bitrate (P frames with a log-normal spread,
   periodic IDRs, LTR anchors, recovery frames sized from nestua-zig's
   x265 and Hantro measurements). A frame not decoded `latency_ms` after
   the encoder is lost; the display holds the last frame, and a gap over
   50 ms is a freeze. Policies choose the MCS and the encoder bitrate:
   `FixedPolicy`, `SnrPolicy` (the reported SNR with an outer loop on the
   pre-FEC packet loss) and `LadderPolicy` (nestua-zig's loss-driven
   ladder). `flight_snr` makes an out-and-back flight.

A minute of link takes about half a second, so e017 sweeps every rung,
rule and policy. `tests/test_m6_link.py` holds the unit tests.

## The RTL blocks (L3, M7)

Verilog-2005 in `rtl/<block>/`, each with a cocotb test that streams the
golden vectors through it and requires zero difference, under Verilator
and Icarus (`rtl/run.sh <block> [SIM=icarus]`, all of them in
`make test-rtl`, with a `verilator -Wall` lint):
- `fft256`: the 16-bit radix-2 FFT/IFFT of fx.Fft, round half to even,
  in two simple-dual-port banks split by address parity, with a 6-clock
  butterfly pipeline (one butterfly a clock, about 1590 clocks a
  transform; M8 changed it from one true-dual-port RAM, which Vivado does
  not infer, and a one-clock butterfly, which missed 100 MHz by 14 ns).
  Twiddles are generated from the twin (`make rtl-tables`, `tools/gen_rtl.py`).
- `cordic`: `cordic_vec` (vectoring), `cordic_rot` (rotation) and
  `angle30` (normalise to 30 bits, then vector), 14-stage pipelines.
- `stf_corr`: the preamble correlator: running sums of the lag-32
  correlation and the energy over 256 samples on delay lines, the
  threshold test and the peak search; `stf_detect` adds the coarse angle
  and NCO increment.
- `nco_rot`: the 32-bit NCO, `cordic_rot` and rot16, which aligns and
  derotates a frame.

Vectors covered: blocks.npz (FFT, CORDIC), every OFDM symbol of the frame
vectors (rx to y), and from the sync vectors the correlator trace, the
detection, the peak, both angles, the pilot FFT, the impulse response and
the aligned frame. `rtl/synth.sh` gives a Yosys resource estimate.

## The receiver in RTL and the board loopback (L3, M8)

The board is the Arty Z7-20 (Zynq XC7Z020: two ARM cores and the FPGA).
Blocks, each bit exact in cocotb (Verilator and Icarus) against the Zig
fixed-point modem and the twins:
- `ldpc_dec`: layered offset min-sum, 16 lanes (every lifting of the MCS
  table is a multiple of 16), the early stop; configured per code by the
  control processor (`harness/rtlcfg.ldpc_cfg`). Tested on blocks.npz,
  every frame vector and all 14 codes of both pilot layouts.
- `rx`: `rx_frame`, the whole fixed-point receiver after alignment: CP
  removal and FFT (`rx_fe`), pilot LS and frequency filter (`rx_chest`),
  phase tracker (`rx_track`), time filter and max-log demapper
  (`rx_demap`), deinterleaver, decoder. Tables and registers come from
  `harness/rtlcfg.rx_cfg`. Every intermediate result and the bits match
  on all 8 frame vectors and the 6 aligned sync frames.
- `chan_emu`: the board's AWGN channel: counter-hashed Box-Muller noise,
  gain and the 12-bit ADC; NumPy twin `harness/chanemu.py`.
- `loopback`: TX frames from the ARM, the emulator, `rx_frame`, the bit
  comparison and error counters behind a register bus; `loopback_axi`
  puts it on the Zynq's AXI GP0. `harness/loopback.EmuLink` is its
  software model, and the cocotb test requires equal counters.

e018 (`make e018`) compares the board model's FER with L2's under AWGN
for every MCS. The board itself: `make fpga` (Vivado: bitstream and
.xsa from `fpga/build.tcl`), `make fpga-ooc` (utilisation and timing of
the loopback alone), `make arm` (the bare-metal error counter in
`fpga/arm/`), `make board` (`tools/board.py`: runs e018's points on the
board over JTAG and requires its counters to equal e018's, writing
`results/e019_board_loopback.json`). Vivado 2026.1 is the Windows
install; the build folder is `BUILD_DIR` (default `/mnt/e/phy-sim-build`).

## The simulator viewer

`make viewer` starts a local web page at http://localhost:8050 (WSL
forwards it, so a Windows browser works too). Each run sends one frame
through the M5 chain (`harness/viewer.capture`, built on `SyncLink`):
the fixed-point transmitter behind its preamble, the TDL channel, the
oscillator (carrier offset set exactly, phase noise, sampling clock),
an optional Wi-Fi burst, noise, AGC and ADC, the synchroniser (real or
genie) and the float or fixed-point receiver with its probes. The page
draws the spectrum, a waterfall, the waveform with the true and the found
frame start, the synchroniser's metric and impulse response, the
constellation before and after equalisation, the channel estimate against
the true channel, the tracker's phase per symbol, the error of every
resource element and the LLR histogram, and counts frame, codeword and
bit errors before and after decoding over 1 to 500 frames. Settings can
be given in the address (`/?channel=tdl-d&doppler_hz=600&theme=dark`).
A new setting builds its link in about 3 s; later frames take 20 ms.
